# 野村證券資料の要約スライド化（/nomura-summary）

## 0. 起動条件（最重要）
- このスキルは、ユーザーがメッセージで **「/nomura-summary」と明示したときだけ** 使う。
- 「野村の資料を要約して」と頼まれても、/nomura-summary がなければ使わない（通常どおり会話で要約する）。
- /nomura-summary の後ろに続く文が要約の指示。対象資料（シリーズ名・号・ファイル名）、枚数、重点などの指定があれば、それを最優先する。

## 1. 前提と置き場所
- 資料の保管先（ユーザーのMac）：`/Users/hideo/disk01/02_Assets(資産)/01_資産運用/01_野村證券_全般/011_公表情報`
- スキル資材：上記フォルダ内の `_要約スキル資材/`
  - `FreeForm_Form16-10(メイリオ).pptx`：必ず使うテンプレート（16:10、白地、メイリオ。EIZOロゴは削除済み）
  - `nomura_deck.py`：作図ヘルパー（python-pptx）。表紙（写真付き）、本文スライド、カード、KPI、フロー、表、CIO VIEWマトリクス、写真・図表の配置（`image_fill` / `image_fit`）、ネイティブ棒グラフ（縦・横・積み上げ、系列ごとのラベル色）を描く
  - `extract_figures.py`：原資料PDFから写真と図表を切り出す
  - `example_build_cio_monthly.py`：CIO Monthly 2026年10月号（16枚、図表・写真入り）の完成例。月次・図表の多い資料の手本
  - `example_build_weekly.py`：野村週報 2026年10月26日号（11枚）の完成例。週次資料の手本
  - `nomura-summary_取扱説明書.md`：ユーザー向けの取扱説明書
- 本文スライドは「タイトルのみ」レイアウトを使う（`Deck.slide()` が自動で選ぶ）。テンプレートからEIZOロゴは削除済みで、ロゴは入れない。
- Macと連携していない、またはフォルダが未接続なら、上記フォルダへのアクセスをリクエストする（パスに記号がなく、通常どおり依頼できる）。承認されなければ、デスクトップアプリの「＋」→「フォルダを追加」を案内して止まる。
- device_bash が使えない環境では、device_stage_files で資料と資材をワークスペースに取り込み、作業後に device_commit_files で書き戻す。

## 2. 対象資料を決める
- 指示に号やファイルがなければ、指定シリーズの最新号を対象にし、何を対象にしたかを最初に一言伝える。
- **前号も取り込む**（同じシリーズフォルダの直前の号）。投資判断・予想値・見出しの変化を比較に使う。
- 動画（mp4）は対象外。同じフォルダの rtf（説明文）は参考にしてよい。
- 「GNL」「可視化(NotebookLM)」フォルダの内容（NotebookLMの出力）は原資料ではないので、要約の根拠にしない。

## 3. 読み取りと素材の切り出し
- テキストは `pdftotext`（-layout なし）で抽出する。段組みで順序が崩れるので、文脈で読み直す。
- **図で表現された判断は、必ずページ画像で確認する**（pdftoppm -r 110 で描画して目視）。例：CIO VIEW のドット位置、前月の点線丸と矢印、マップの象限。PDFの印刷ページ番号とファイル上のページ番号はずれることがある。
- **写真と図表を切り出す**：`python3 extract_figures.py <資料.pdf> <出力dir>`
  - 出力される `contact.jpg` を必ず目視し、切れ・はみ出しがあれば `crop()` で座標を直して切り直す。
  - 「図表N」の見出しがないグラフ（例：「国内株式の4局面とEPS」、スプレッド推移、ブレークイーブンインフレ率、巻末の「1年間の主要資産の推移」）は自動では拾えない。ページを描画して位置を確かめ、`crop()` で切り出す。
  - 横長の装飾帯や小さなアイコンは使わない。
  - 野村週報など、図に「図表N」の見出しがない資料は自動ではほとんど拾えない。各ページの図の位置を `pdftotext -bbox-layout` と描画画像で確かめ、`crop()` で切り出す（右側の本文段を含めないよう x 範囲に注意）。
- 抽出した事実は「事実・数値・出典ページ」の一覧にまとめてから構成を考える。

## 4. まとめ方の原則
- 構成はピラミッド型：表紙 → 今月の結論（3点）→ 判断・予想の一覧（前号比較）→ テーマ別（1枚1メッセージ）→ 参考ページ → 今後の注目点・判断変更のトリガー → 用語ミニ解説と出典。
- **枚数の既定は12〜16枚。** 図表が少ない資料は8〜12枚。ユーザーの指示があればそちらを優先する。
- スライドタイトルは結論の文で書く（例：「REIT：金利上昇が逆風、先進国REITを引き下げ」）。24pt・太字、目安は24字以内。
- **グラフィカルに仕上げる。原資料に写真や図表があれば、なるべく採用する。**
  - 表紙：原資料の表紙写真を右側に全面配置する（`cover(..., photo=...)`）。
  - 地域・テーマの見出し：原資料の写真をカード上部に敷く（`image_fill`）。
  - テーマ別スライド：該当する原資料の図表を左に置き（2枚組なら並べる）、右に要点パネル、下に「判断／ひとこと」の帯、を基本形にする（`image_fit` と例の `two_charts` / `panel`）。
  - 図表の下には「原資料 p.X 図表N」を必ず入れる（`image_fit(caption=...)`）。ページは印刷ページ番号で書く。
  - 判断の一覧（CIO VIEW など）、因果フロー、比較カード、トリガー表は、自作の図解（編集できる図形）で描く。
  - 原資料に図がなく、本文に数値がある場合は、ネイティブの棒グラフやKPIタイルで示す。
  - 写真や図版は原資料からのみ使う。Webなどから画像を持ってこない。
- **数値は原資料に書かれたものだけを使う。** 図から目分量で読んだ値は書かない。図から読み取れる傾向だけを書く場合は「傾向のみ記載」と注記する。
- 原資料以外の情報（最新の市場データなど）は加えない。ユーザーに頼まれた場合だけ、「補足」と明記して分ける。
- 各スライドのノートに出典ページを書く。最終スライドには、出典（資料名・号・判断の基準日）と、要約である旨の注記（図表・写真は原資料による）を入れる。
- 配色ルール：上昇・引き上げ・追い風は赤（C00000）、下落・引き下げ・逆風は紺（1F497D）、中立はグレー。CIO VIEW の5段階は `C.SCALE` を使う。
- 強調に縁の色帯やタイトル下線は使わない。淡色の全面ボックスで代用する（`callout`）。

## 5. シリーズ別の型
- **CIO Monthly**（月次・約20ページ）
  - 結論は表紙の「今月の投資戦略」3点を使う。
  - CIO VIEW（資産クラス4区分＋10資産、5段階）を `view_matrix` で描き、前月から変わった資産は前月位置を点線丸＋矢印で示す。
  - 直近2か月の判断変更履歴を入れる。
  - 「ファンダメンタルズ・バリュエーションマップ」の図と読み方を1枚にする。
  - ストラテジー・コメントの図表1〜6を、それぞれテーマ別スライドに使う。
  - 「今月の投資判断のポイント」の図（4局面とEPS、スプレッド、BEI など）と、巻末の「1年間の主要資産の推移」も使う。
  - 「〜の場合は引き下げを検討」と書かれた箇所は、トリガー表にまとめる。
- **野村マンスリー投資会議（要約）**（月次・8ページ）
  - 「株価・金利・為替の予想サマリー」を、直近値と予想値の表、およびネイティブの棒グラフ／折れ線グラフにする。
  - 前号と予想値を比べ、上方修正（赤▲）・下方修正（紺▼）を色分けする。
  - 経済・為替・株価の見通しについては、メインシナリオとリスク要因を対比させる。
- **グローバル為替・金利展望／国際金融為替（M&W）**
  - 通貨別の予想値・レンジを表とグラフにする。
  - 原資料のチャートを使い、金融政策と金利差から為替に至る因果をフロー図で示す。
- **野村週報／週刊チャート展望**（週次）
  - 8〜11枚に絞る。標準構成：表紙（表紙写真）→ 今週の結論＋前号からの変化（日経平均の節目・主要通貨の対円レート）→ オピニオン（原資料の図＋記載数値から作るグラフ）→ マーケットビュー（日本・グローバル）→ 米国・為替（指数化チャートの表の値で前号と比較）→ 今週の予定（日別カレンダー）→ 今週のトピック → 野村アナリストの眼 → マネーコラム → 用語と出典。
  - 決算発表スケジュールの一覧ページは通常は使わない。
- **CIO Quarterly／テーマ銘柄／その他**
  - 上の原則で汎用の構成にする。銘柄リストは表にまとめ、推奨とは書かず、資料の表現をそのまま使う。

## 6. 作成手順
1. 資材一式と対象PDF（＋前号）を取り込む。
2. `extract_figures.py` で写真・図表を切り出し、目視で確認・修正する。使うファイルは分かりやすい名前（`photo_cover.jpg`、`fig2_1.png` など）にコピーする。
3. 月次・図表の多い資料は `example_build_cio_monthly.py`、週次は `example_build_weekly.py` を手本に `build_<シリーズ>_<号>.py` を書く。引数は `<資材dir> <テンプレート> <出力.pptx> <画像dir>`。
4. 本文エリアは x 0.4〜9.6 in、y 0.95〜5.35 in。右下のスライド番号に重ねない。
5. 本文は10.5〜12pt、注記は9pt以上にする。

## 7. 検証（必須）
- anthropic-skills:pptx スキルを読み込み、その `scripts/office/validate.py 出力.pptx --original テンプレート.pptx` を実行する。
- PDFに変換して全スライドを画像で確認し、次の点を直す。
  - はみ出し・重なり・不自然な改行（単位だけが次の行に落ちていないかも見る）
  - 図表の切れ
  - 余白の偏り
- サンドボックスにメイリオはないので、プレビューは近似と考え、文字量には1割程度の余裕を持たせる。
- 数値と判断を原資料と突き合わせる（特にCIO VIEWの段階と前月比較）。

## 8. 保存と報告
- 保存先：
  - 号ごとのフォルダがある場合：そのフォルダ内の `可視化(Claude)/`
  - CIO Monthly：`CIO_Monthly/<年>/解説CIO_Monthly(<年>年<月>月号)/可視化(Claude)/`
  - PDFがシリーズ直下に並んでいる場合：`<シリーズ>/可視化(Claude)/`
- ファイル名：`<資料名>(<号>)_要約.pptx`
- 返答は短くする。対象号、枚数、今号の要点1〜2行、保存先を伝え、ファイルも送る。

## 9. 資材と説明書の保守
- 資材（テンプレート・スクリプト・手本）を変更したら、必ず `_要約スキル資材/` に書き戻し、`nomura-summary_取扱説明書.md` の該当箇所と改訂履歴も同時に更新する。
- このSKILL.mdの内容を変えたときは、ユーザーにスキルの更新保存を依頼する（Claudeの設定に保存されたスキルは自動では更新されない）。
- 作ったデッキは取扱説明書の「作成済みのデッキ」表に追記する。
